## 1. 概述

本文档描述「手机考试」从**创建考试 → 获取试题 → 提交答案 → 结算成绩**所需的全部接口。

手机考试的核心特征：

- 每场考试为**单张试卷**，交卷时一次性提交全部答案；
- 创建考试时必须使用 `type=2`，否则会被平台归类为模拟考试；
- 结算必须调用 `CEndTimeOne`，并携带 AES/RSA 加密参数；
- 每场满分 8 分，每日上限 16 分（两场）。

适用范围：服务端对接、自动化客户端、测试工具。本文档不包含模拟考试、练习、签到等其他业务流程。

## 2. 环境与公共约定

### 2.1 基础地址

```text
Base URL: http://<platform-host>:<port>
示例:     http://61.150.84.25:100
```

`Base URL` 由部署环境决定，不得硬编码到客户端业务代码中。

### 2.2 请求约定

| 项 | 约定 |
|---|---|
| 协议 | HTTP/1.1（平台为 ASP.NET MVC + nginx）|
| 请求方法 | GET / POST |
| POST 编码 | `application/x-www-form-urlencoded` |
| 会话 | Cookie（首次请求验证码接口后由服务端下发 `ASP.NET_SessionId`）|
| AJAX 标识 | 建议携带 `X-Requested-With: XMLHttpRequest` |
| 字符集 | UTF-8 |

### 2.3 响应类型

| 类型 | 说明 |
|---|---|
| JSON | 形如 `{"success":true,"data":...,"message":""}` |
| 文本 | `|` 分隔字符串（登录/会话/结算结果）|
| HTML | 考试页返回整页 HTML，数据内嵌在 `var vData={...};` |

### 2.4 `Esdt` 参数混淆（平台协议）

部分接口参数（创建考试后的 `SetOnlineTestOne`、登录等）必须经过平台自定义的 `Esdt()` 混淆。

算法定义：

1. 对输入字符串逐个 UTF-16 码元取十进制字符串并拼接；
2. 追加 `^`；
3. 追加每个十进制串的长度，用 `,` 连接；
4. 对整个结果执行 ECMAScript 遗留 `escape()`：
   - `A-Z a-z 0-9 @ * _ + - . /` 原样保留；
   - 其余码元 `< 0x100` → `%XX`（大写十六进制）；
   - 其余码元 `>= 0x100` → `%uXXXX`（大写十六进制）。

示例：

```text
输入: 123
十进制串: 495051
长度串:   2,2,2
拼接:    495051^2,2,2
escape:  495051%5E2%2C2%2C2
结果:    495051%5E2%2C2%2C2
```

```text
输入: A1
十进制串: 6549
长度串:   2,2
拼接:    6549^2,2
escape:  6549%5E2%2C2
结果:    6549%5E2%2C2
```

> 说明：`^` 会被 `escape()` 编码为 `%5E`，`,` 编码为 `%2C`。

## 3. 前置条件：登录与会话

> 完整登录与会话说明见《登录接口文档》，本节仅保留调用前提。

以下接口仅用于建立会话、获取 `userId` 与当前题库 `examTypeId`，是手机考试接口的调用前提。

### 3.1 预建会话（获取 Cookie）

```http
GET /Home/GetValidateCode
```

响应为验证码图片（内容可忽略），目的是让服务端下发 `ASP.NET_SessionId`。

### 3.2 登录

```http
POST /PersonWap/GetPersonInfo
Content-Type: application/x-www-form-urlencoded
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `idcard` | string | 是 | 身份证号，需 `Esdt` 编码 |
| `pwd` | string | 是 | 密码，需 `Esdt` 编码 |
| `yzm` | string | 是 | 固定 `auto` |
| `openid` | string | 是 | 固定空串 |
| `style` | string | 是 | 固定 `0` |
| `auto` | string | 是 | 固定 `true` |

响应（`|` 分隔）：

```text
|<userId>|<userName>|<sessionHash>|<returnCode>
```

- 首段为空表示成功；非空则为服务端错误文案；
- `userId` 即后续所有接口的 `pid`；
- 示例：

```text
|ec5dab3e-xxxx-xxxx-xxxx-xxxxxxxxxxxx|张小赞|hash|0008
```

### 3.3 会话快照 / 当前题库

```http
POST /PersonWap/FirstIndexOne
Content-Type: application/x-www-form-urlencoded
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pid` | string | 是 | 登录返回的 `userId` |

响应（`|` 分隔）：

```text
|<0>|<returnCode>|<userId>|<题库名称>|...|<examTypeId>|...
```

| 下标 | 含义 |
|---|---|
| 0 | 错误文案，空表示成功 |
| 4 | 当前题库名称 |
| 6 | `examTypeId`（题库 ID，后续列表接口使用）|

## 5. 接口定义

### 5.1 查询可开考试卷

```http
GET /ExamManger/P_Paper/SelectCanRunListOne?rows=20&page=1&pid={pid}&examtypeid={examTypeId}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `rows` | int | 是 | 每页条数，示例 `20` |
| `page` | int | 是 | 页码，从 `1` 开始 |
| `pid` | string | 是 | 用户 ID |
| `examtypeid` | string | 是 | 题库 ID（来自 3.3）|

响应示例：

```json
{
  "totalCount": 1,
  "success": true,
  "error": "",
  "data": [
    {
      "PaperId": "2069a073-fe4d-4065-9cad-e1f5f951de08",
      "PaperName": "2025陕西煤业矿业公司主要负责人",
      "TotalScore": 100.0,
      "PassingGrade": 80.0
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `data[].PaperId` | string | 试卷 ID，创建考试使用 |
| `data[].PaperName` | string | 试卷名称 |
| `data[].TotalScore` | number | 试卷总分 |
| `data[].PassingGrade` | number | 及格分 |

错误处理：

- `data` 为空数组：当前题库没有可开考试卷；
- `success=false`：读取 `error` 字段。

### 5.2 检查未完成考试（可选）

```http
POST /ExamManger/P_ExamDetail/ExistsNoFinish
Content-Type: application/x-www-form-urlencoded
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `PaperId` | string | 是 | 试卷 ID |
| `pid` | string | 是 | 用户 ID |
| `type` | int | 是 | 固定 `1` |

响应示例：

```json

```

| `data` | 含义 |
|---|---|
| `0` | 该试卷没有未完成考试 |

- `data=0`：直接创建考试；
- `data>0`：可继续创建新考试（实测允许），或由产品决定先处理未完成记录。

### 5.5 获取考试页（试题数据）

```http
GET /P_ExamDetail/OnlineTestOne
```

响应为完整 HTML，试题数据内嵌在：

```js
var vData = { ... };
```

解析方式：截取 `var vData=` 到第一个 `};` 之间的 JSON 对象。

#### vData 关键字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `AllCount` | string | 题目总数（如 `"100"`）|
| `AllQuestionArray` | string | 题目记录，`|` 分隔，每条 22 个字段 |
| `AllQuestionType` | string | 题型分组说明 |
| `Code` | string | 业务返回码（如 `0008`）|
| `ExamTypeId` | string | 题库 ID |
| `ExamTypeName` | string | 题库名称 |
| `my` | string | RSA 公钥 XML（结算加密使用）|
| `Title` | string | 页面标题 |

#### `AllQuestionArray` 单条记录字段（`,` 分隔，共 22 项）

| 下标 | 含义 | 示例 |
|---|---|---|
| 0 | 答题记录 ID | `1^0$1$2` |
| 1 | 题目 GUID | `33b4a29e-...` |
| 2 | 排序 | `1` |
| 3 | 标记 | `0` |
| 4 | **用户答案**（提交前为空）| 空 |
| 5 | 提示 | `0` |
| 6 | 对错标记 | 空 |
| 7 | 卷别 | 空 |
| 8 | 修正 | 空 |
| 9 | 试卷试题 ID | 空 |
| 10 | 分值 | `1` |
| 11 | 顺序号 | `1` |
| 12 | 得分 | `-1` |
| 13 | **正确答案（显示顺序）** | `A` / `ABCD` / `Y` / `N` |
| 14 | 题型 | `1` 单选、`2` 多选、`3` 判断 |
| 15 | 题干（URL 编码）| `4.%e7%9f%bf...` |
| 16 | 选项文本（URL 编码，`#` 分隔）| `A.xxx#    B.xxx` |
| 17 | 保留 | 空 |
| 18 | 服务端答案编码 | `A` |
| 19 | 保留 | 空 |
| 20 | 来源标记 | 空 / `标准` |
| 21 | 来源说明 | `试题编号：...` |

> 考试交卷使用 **字段 13** 作为用户答案写入字段 4；字段 18 不属于手机考试交卷流程。

### 5.6 提交全部答案

```http
POST /Home/DoWriteAnswerAll
Content-Type: application/x-www-form-urlencoded
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `answer` | string | 是 | 拼接后的答案串 |
| `ksmxid` | string | 是 | 考试会话 ID（明文）|

`answer` 构造规则：

1. 对每条题目记录按 `,` 拆分；
2. 取前 15 个字段（下标 0–14）；
3. 将字段 4（用户答案）设置为字段 13（正确答案）；
4. 每条记录用 `,` 重新连接；
5. 所有记录用 `|` 连接。

伪代码：

```text
records = vData.AllQuestionArray.split('|')
answers = []
for r in records:
    f = r.split(',')
    f[4] = f[13]
    answers.push(join(f[0..14], ','))
payload.answer = join(answers, '|')
payload.ksmxid = ksmxid
```

响应示例：

```json
{
  "totalCount": 1,
  "success": true,
  "error": "",
  "singleInfo": "",
  "data": [{ "Result": "" }]
}
```

> 该接口只负责写入答案，**不返回分数**；分数在结算接口返回。

### 5.7 结算成绩（加密）

```http
POST /Home/CEndTimeOne
Content-Type: application/x-www-form-urlencoded
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ksmxid` | string | 是 | 考试会话 ID（明文）|
| `mxid2` | string | 是 | AES 加密后的 `ksmxid`（Base64）|
| `mxid3` | string | 是 | RSA 加密后的 AES 密钥（Base64）|

#### 加密规范

1. 生成随机 16 字节密钥 `K`（AES-128）；
2. `aesKeyB64 = Base64(K)`；
3. `mxid2 = Base64( AES-128-ECB-PKCS7( UTF8(ksmxid), K ) )`；
4. 从 `vData.my` 解析 RSA 公钥：

```xml
<RSAKeyValue>
  <Modulus>...</Modulus>
  <Exponent>AQAB</Exponent>
</RSAKeyValue>
```

5. `mxid3 = Base64( RSA-PKCS1-v1.5( UTF8(aesKeyB64), Modulus, Exponent ) )`。

参考实现（C# / .NET）：

```csharp
var key = RandomNumberGenerator.GetBytes(16);
var aes = Aes.Create();
aes.Mode = CipherMode.ECB;
aes.Padding = PaddingMode.PKCS7;
aes.Key = key;
var mxid2 = Convert.ToBase64String(
    aes.CreateEncryptor().TransformFinalBlock(
        Encoding.UTF8.GetBytes(ksmxid), 0, Encoding.UTF8.GetByteCount(ksmxid)));

var rsa = RSA.Create();
rsa.ImportParameters(new RSAParameters {
    Modulus = Convert.FromBase64String(modulusB64),
    Exponent = Convert.FromBase64String(exponentB64)
});
var mxid3 = Convert.ToBase64String(
    rsa.Encrypt(Encoding.UTF8.GetBytes(Convert.ToBase64String(key)),
                RSAEncryptionPadding.Pkcs1));
```

#### 响应

成功：

```text
您的分数为：100,合格！|100|合格！
```

| 段 | 含义 |
|---|---|
| 0 | 成绩文案（可直接展示）|
| 1 | 分数（如 `100`）|
| 2 | 是否合格（如 `合格！`）|

失败：

```text
error
```

常见失败原因：

| 现象 | 原因 |
|---|---|
| `error` | `mxid2` / `mxid3` 缺失、为空或加密不正确 |
| `error` | `ksmxid` 不存在或已结算 |
| 空响应 | 会话失效或网络错误 |

## 6. 完整调用示例（伪代码）

```text
session = warmUp()                       // GET /Home/GetValidateCode
login = login(idcard, pwd)               // POST /PersonWap/GetPersonInfo
userId = login.parts[1]
info = firstIndexOne(userId)             // POST /PersonWap/FirstIndexOne
examTypeId = info.parts[6]

papers = selectPapers(pid=userId, examtypeid=examTypeId)
paper = papers[0]

exists = existsNoFinish(paper.PaperId, userId)   // data=0

created = createTempExam(paper.PaperId, userId, type=2)
ksmxid = created.data

setOnlineTestOne(ksmxid, style='0', pid=userId)

html = GET /P_ExamDetail/OnlineTestOne
vData = parseVData(html)
answers = buildAnswers(vData.AllQuestionArray)

doWriteAnswerAll(answer=answers, ksmxid=ksmxid)
result = cEndTimeOne(ksmxid, aesRsaEncrypt(ksmxid, vData.my))
score = result.split('|')[1]
```

## 7. 错误处理与重试建议

| 场景 | 建议 |
|---|---|
| 会话失效（响应为登录页/错误文案）| 重新执行 3.1–3.2 |
| `CreateTempExamOne` 失败 | 检查 `PaperId`、`PersonId`、`type=2` |
| `SetOnlineTestOne.success != true` | 检查 Esdt 编码与 `style=0` |
| `DoWriteAnswerAll.success != true` | 检查 `answer` 拼接格式与 `ksmxid` |
| 结算返回 `error` | 检查 AES 模式（ECB）、填充（PKCS7）、RSA 填充（PKCS#1 v1.5）与 Base64 |
| 网络超时 | 仅对幂等查询重试；创建/提交/结算不要重复调用 |

## 12. 记录标签与查询口径（2026-10-27 实测补充）

平台会把 `CreateTempExamOne(type=2)` 产生的记录标记为 **「手机自测」**，而不是「手机考试」。

| 创建参数 | 成绩页标签 | 查询过滤 |
|---|---|---|
| `type=2` | 手机自测 | `GetMyExamListOne?type=2` |
| `type=1` | 手机模拟 | `GetMyExamListOne?type=3` |
| `type=0`（默认）| 理论考试 | 不包含手机考试记录 |

实测：

- `GetMyExamListOne?type=0` 只返回理论考试，**不能**用它判断手机考试是否创建/结算；
- `GetMyExamListOne?type=2` 返回今天 11:36 的 100 分记录（手机自测）；
- 成绩页「手机考试」tab 为空，「手机模拟」tab 有今天的记录。

结论：恢复/对账必须带正确 `type` 过滤；空列表不等于未提交。
