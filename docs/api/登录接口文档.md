## 1. 概述

本文档描述平台移动端的**登录与会话建立**流程，是所有业务接口（考试、练习、签到、阅读等）的公共前置。

核心特征：

- 登录前必须先请求验证码接口，让服务端下发 `ASP.NET_SessionId`；
- 登录参数中的身份证号与密码必须经过平台 `Esdt()` 混淆；
- 验证码模式固定为 `yzm=auto`（不展示验证码）；
- 登录响应是 `|` 分隔文本，不是 JSON；
- 后续所有接口复用同一份 Cookie 会话。

适用范围：服务端对接、自动化客户端、测试工具。本文档不包含任何业务接口。

## 2. 环境与公共约定

### 2.1 基础地址

```text
Base URL: http://<platform-host>:<port>
示例:     http://61.150.84.25:100
```

`Base URL` 由部署环境决定，不得硬编码。

### 2.2 请求约定

| 项 | 约定 |
|---|---|
| 协议 | HTTP/1.1（ASP.NET MVC + nginx）|
| 方法 | `GET` / `POST` |
| POST 编码 | `application/x-www-form-urlencoded` |
| AJAX 标识 | 建议携带 `X-Requested-With: XMLHttpRequest` |
| 会话 | Cookie（`ASP.NET_SessionId` 等）|
| 字符集 | UTF-8 |

### 2.3 会话要求

- 登录前必须先调用验证码接口，否则服务端无法关联会话；
- 后续接口必须复用同一 Cookie 容器，不能每次新建客户端；
- 会话过期表现为：接口返回登录页 HTML、或响应首段出现错误文案。

## 3. `Esdt` 参数混淆

身份证号与密码必须经 `Esdt()` 处理后再提交。

算法定义：

1. 对输入字符串逐个 UTF-16 码元取十进制字符串并拼接；
2. 追加 `^`；
3. 追加每个十进制串的长度，用 `,` 连接；
4. 对整个结果执行 ECMAScript 遗留 `escape()`：
   - `A-Z a-z 0-9 @ * _ + - . /` 原样保留；
   - 其余码元 `< 0x100` → `%XX`（大写十六进制）；
   - 其余码元 `>= 0x100` → `%uXXXX`（大写十六进制）。

示例：

```text
输入: 123
拼接: 495051^2,2,2
escape: 495051%5E2%2C2%2C2
结果: 495051%5E2%2C2%2C2
```

```text
输入: A1
拼接: 6549^2,2
escape: 6549%5E2%2C2
结果: 6549%5E2%2C2
```

> `^` → `%5E`，`,` → `%2C`。

## 4. 业务流程

```text
GET  /Home/GetValidateCode         获取会话 Cookie（内容可忽略）
        │
        ▼
POST /PersonWap/GetPersonInfo      提交 Esdt 编码后的账号密码
        │
        ▼
解析竖线响应 → userId
        │
        ▼
POST /PersonWap/FirstIndexOne      校验会话，读取当前题库
        │
        ▼
后续业务接口（复用同一 Cookie）
```

---

## 5. 接口定义

### 5.1 预建会话（验证码）

```http
GET /Home/GetValidateCode
```

响应为验证码图片（`image/*`），客户端**不需要识别图片内容**，调用目的只是让服务端下发会话 Cookie。

响应成功后必须保存 `Set-Cookie`，例如：

```text
ASP.NET_SessionId=xxxxxxxxxxxxxxxx
```

常见错误：

| 现象 | 处理 |
|---|---|
| 403 / 302 | 检查是否携带了正确的 Host 与路径 |
| 无 Set-Cookie | 使用同一个 Cookie 容器继续后续请求 |

---

### 5.2 登录

```http
POST /PersonWap/GetPersonInfo
Content-Type: application/x-www-form-urlencoded
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `idcard` | string | 是 | 身份证号，需 `Esdt` 编码 |
| `pwd` | string | 是 | 密码，需 `Esdt` 编码 |
| `yzm` | string | 是 | 固定 `auto`（自动验证码模式）|
| `openid` | string | 是 | 固定空串 |
| `style` | string | 是 | 固定 `0` |
| `auto` | string | 是 | 固定 `true` |

请求示例（表单）：

```text
idcard=495051%5E2%2C2%2C2
pwd=...（密码的 Esdt 编码）
yzm=auto
openid=
style=0
auto=true
```

响应为 `|` 分隔文本：

```text
|<userId>|<userName>|<sessionHash>|<returnCode>
```

成功示例：

```text
|ec5dab3e-xxxx-xxxx-xxxx-xxxxxxxxxxxx|张小赞|hash|0008
```

失败示例：

```text
密码错误
```

| 位置 | 含义 |
|---|---|
| 第 0 段 | 成功时为空；失败时为错误文案 |
| 第 1 段 | `userId`，即后续接口的 `pid` |
| 第 2 段 | 用户姓名 |
| 第 3 段 | 会话哈希 |
| 第 4 段 | 返回码，如 `0008` |

解析规则：

- 不能对响应整体 `trim()`，否则会破坏用于判断成功的开头分隔符；
- 空响应视为失败；
- 首段非空即失败，直接把该文案作为错误提示。

---

### 5.3 会话校验 / 当前题库

```http
POST /PersonWap/FirstIndexOne
Content-Type: application/x-www-form-urlencoded
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pid` | string | 是 | 登录返回的 `userId` |

响应（`|` 分隔）：

```text
|<0>|<returnCode>|<userId>|<题库名称>|...|<examTypeId>|...
```

| 下标 | 含义 |
|---|---|
| 0 | 空 = 会话有效；非空 = 错误文案 |
| 4 | 当前题库名称 |
| 6 | `examTypeId`（题库 ID）|

用途：

- 判断登录是否真正生效（首段为空）；
- 获取当前题库名称与 `examTypeId`，供考试/练习接口使用。

## 6. 完整调用示例（伪代码）

```text
client = HttpClient(cookieJar)

client.get('/Home/GetValidateCode')                 // 建立会话

login = client.postForm('/PersonWap/GetPersonInfo', {
    idcard: esdt(idcard),
    pwd:    esdt(password),
    yzm:    'auto',
    openid: '',
    style:  '0',
    auto:   'true',
})

parts = login.split('|')
if (parts[0] != '') throw parts[0]

userId = parts[1]

info = client.postForm('/PersonWap/FirstIndexOne', { pid: userId })
infoParts = info.split('|')
if (infoParts[0] != '') throw infoParts[0]

bankName = infoParts[4]
examTypeId = infoParts[6]
```

## 7. 错误处理与重试

| 场景 | 建议 |
|---|---|
| 登录失败（首段有文案）| 直接展示错误，不要自动重试，避免锁定 |
| 验证码接口失败 | 重试一次；仍失败检查网络与 Host |
| 会话失效 | 重新执行 5.1–5.2 |
| 网络超时 | 登录是写操作，不盲目重试；先确认会话状态再重登 |
| Cookie 丢失 | 确认整个流程使用同一个 Cookie 容器 |

---

## 8. 安全要求

- 禁止在日志、崩溃上报中输出身份证号、密码或完整 Cookie；
- 客户端如需记住账号，只允许保存身份证号，密码不得明文落盘；
- 生产环境应使用 HTTPS；如部署为 HTTP，需在传输层另行评估风险；
- `pwd` 的 Esdt 编码只是平台协议混淆，不构成加密，不能当作安全措施。
