---

## 1. 概述

本文档覆盖三类积分查询：

| 查询 | 接口 | 用途 |
|---|---|---|
| 今日任务积分 | `GetPersonTodayAccumulateOne` | 首页任务卡、判断今天还差什么 |
| 积分明细 | `GetMyAccumulateListOne` | 积分流水、核对入账 |
| 积分规则 | `GET /PersonWap/MyRule` | 平台官方规则说明页 |

所有接口都需要登录会话，`pid` 为登录返回的 `userId`。

---

## 2. 公共约定

### 2.1 基础地址与请求

```text
Base URL: http://<platform-host>:<port>
示例:     http://61.150.84.25:100
```

| 项 | 约定 |
|---|---|
| 会话 | Cookie（先登录）|
| 方法 | 见各接口 |
| POST 编码 | `application/x-www-form-urlencoded` |
| 字符集 | UTF-8 |

### 2.2 `Esdt` 混淆

标注「Esdt」的参数必须经过平台 `Esdt()` 混淆：

1. 逐个 UTF-16 码元取十进制字符串拼接；
2. 追加 `^`；
3. 追加各十进制串长度（`,` 连接）；
4. 执行 ECMAScript `escape()`（`^`→`%5E`、`,`→`%2C`）。

示例：

```text
输入: 123
结果: 495051%5E2%2C2%2C2
```

## 3. 今日任务积分

```http
GET /AccumulateManger/S_Accumulate/GetPersonTodayAccumulateOne?pid={Esdt(userId)}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pid` | string | 是 | 用户 ID（Esdt）|

响应示例：

```json
{
  "success": true,
  "data": [
    {
      "AccumulateTypeName": "每日",
      "Sort": 1,
      "AccumulateId": "8e5238eb-519f-41dd-b3f0-3eabc0a82a9b",
      "PersonId": "ec5dab3e-...",
      "AccumulateName": "签到",
      "AccumulateRule": "每日签到1分，连续登录每日多1分，每日最多3分",
      "Accumulate": 1,
      "MaxAccumulate": 3,
      "CurAccumulate": 2,
      "CurAccumulateState": "",
      "Criterion": "CheckIn"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `AccumulateName` | string | 任务名称 |
| `AccumulateRule` | string | 规则文案（服务端下发）|
| `Accumulate` | int | 单次/单档积分 |
| `MaxAccumulate` | int | 每日上限 |
| `CurAccumulate` | int | 今日已得积分 |
| `CurAccumulateState` | string | 进度描述，如 `已答285题/获得5分`、`已考0个/未考0个` |
| `Criterion` | string | 任务标识，见下表 |
| `AccumulateId` | string | 累计项 ID |
| `Sort` | int | 排序 |

### 3.1 `Criterion` 对照表

| Criterion | 名称 | 规则 | 上限（实测）|
|---|---|---|---|
| `CheckIn` | 签到 | 每日签到 1 分，连续登录每日多 1 分 | 3 |
| `StudyKnowledge` | 知识学习 | 每日学习 1 个知识点 1 分 | 1 |
| `MockExam` | 模拟考试 | 每日及格计 3 分、满分 4 分 | 8 |
| `MobileExam` | 手机考试 | 每日及格计 6 分、满分 8 分 | 16 |
| `Course` | 视频学习 | 每日最低 5 分钟 | 1 |
| `StudyTime` | 练习时长 | 每日有效时长超过 2 小时加 10 分 | 10 |
| `MobileExercises` | 手机练习 | 每日每练习 50 题加 1 分 | 6 |

> 上表“上限”以接口返回的 `MaxAccumulate` 为准。注意：积分规则页写“手机考试每日最多 8 分”，但任务接口 `MaxAccumulate=16` 且实测两场 100 分后确实到 16/16，说明**规则页文案可能滞后，应以任务接口字段为准**。

### 3.2 规则文案解析

进度与阈值可能随服务端配置变化，建议动态解析而不是写死：

```text
每练习 N 题 1 分   → RegExp("每练习\\s*(\\d+)\\s*题")
今日已答题数       → RegExp("已答(\\d+)题") 作用于 CurAccumulateState
剩余题数           = MaxAccumulate × N − 已答题数
```

### 3.3 延迟入账

积分不是实时写入：

- 考试/练习结算成功后，`CurAccumulate` 可能仍为 0；
- 实测手机练习从 0 分到 6 分存在延迟，最终正常入账；
- 客户端应**轮询**该接口（建议每 10–15 秒，最多 90 秒）确认，而不是结算后立即判定失败。

## 4. 积分明细

```http
GET /ArchiveManger/D_PersonAccumulate/GetMyAccumulateListOne?pid={Esdt(userId)}&page=1&rows=10
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pid` | string | 是 | 用户 ID（Esdt）|
| `page` | int | 是 | 页码，从 1 开始 |
| `rows` | int | 是 | 每页条数 |

响应示例：

```json
{
  "success": true,
  "data": [
    {
      "PersonAccumulateId": null,
      "PersonId": "ec5dab3e-...",
      "Accumulate": 2,
      "ExamDetailId": "",
      "AccumulateName": "签到",
      "AccumulateDate": "2026-10-27T01:45:24.977",
      "CreateDate": null,
      "ReduceName": "",
      "ReduceType": 0
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `AccumulateName` | string | 积分来源（签到/知识学习/手机考试等）|
| `Accumulate` | int | 本次积分，可为负（扣减）|
| `AccumulateDate` | string | 入账时间（ISO）|
| `ExamDetailId` | string | 关联考试记录，非考试为空串 |
| `ReduceName` | string | 扣减名称 |
| `ReduceType` | int | 扣减类型，`0` 表示正常加分 |
| `PersonAccumulateId` | string? | 明细 ID（可能为 null）|
| `CreateDate` | string? | 创建时间（可能为 null）|

## 5. 积分规则页

```http
GET /PersonWap/MyRule?pid={userId}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pid` | string | 是 | 用户 ID（明文）|

响应为 HTML 片段，正文规则（实测原文）：

```text
积分规则

签到：
每日签到1分，连续登录每日多1分，每日最多3分。

试题纠错：
纠错一题审核后加10分。

模拟考试：
每日每次及格计3分，满分计4分，每日最多8分。

手机考试：
每日每次及格计6分，满分计8分，每日最多8分。

练题积分：
模拟考试、手机考试每日每答50道题加1分，最多6分。

全员考试：
得分即为积分，80分以下不积分，月度内以最高得分为准；
90分以上为优秀，加20分，月度内以最高得分为准；
考试满分加30分，月度内以最高得分为准。

学习：
每日视频学习最低5分钟，每日最多1积分。
知识点学习，每日最多1分
```

说明：

- 该页是**服务端静态 HTML**，可能落后于任务接口的配置；
- 规则页与任务接口冲突时，以任务接口的 `MaxAccumulate` 与实际入账为准；
- 解析规则页时按 `<li>` 提取文本即可，无需登录额外接口。

## 6. 完整调用示例（伪代码）

```text
warmUp()
login = login(idcard, pwd)
userId = login.parts[1]

tasks = get('/AccumulateManger/S_Accumulate/GetPersonTodayAccumulateOne', {
    pid: esdt(userId)
})

for t in tasks.data:
    print(t.Criterion, t.CurAccumulate, '/', t.MaxAccumulate, t.CurAccumulateState)

detail = get('/ArchiveManger/D_PersonAccumulate/GetMyAccumulateListOne', {
    pid: esdt(userId), page: 1, rows: 10
})

rules = get('/PersonWap/MyRule', { pid: userId })   // HTML，展示用
```

## 7. 错误处理

| 场景 | 建议 |
|---|---|
| `success=false` | 展示 `message`，不要循环重试 |
| 任务数组为空 | 账号未配置积分任务，或接口异常 |
| 结算后积分不涨 | 等待并轮询（见 3.3），不要立即判失败 |
| 规则页与接口冲突 | 以接口字段和实际入账为准 |
| 会话失效 | 重新登录 |
